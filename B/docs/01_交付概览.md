# 1 交付概览：B 这一摊到底交了什么

## 1.1 四件交付物与它们的用处

分工表给 B 的关键交付物是「素材库、案例库、授权表、数据字典」。这四样在本包里不是四个文件夹，而是四条能互相校验的链：图片进 `assets/`，元数据进 `data/*.csv`，授权行进 `license_table.csv`，字段定义进第 6 节。任何一张图都能反查到来源、作者、许可和质检结论。

| 交付物 | 分工表位置 | 现在长什么样 | 谁在用 |
|---|---|---|---|
| 素材库 | W2 36 种素材 | `assets/cutout/Pxx/Pxx_front_源.png` + `assets_manifest.csv` 36 行 | D 合成、E 画布 |
| 案例库 | W2 100 张案例 | `cases_quota.csv` 30 格配额 + `cases_manifest.csv` 元数据 | C 检索与校准、E 案例页 |
| 授权表 | W1 授权白名单 | `license_table.csv` 一行一张 + `logs/collect_*.jsonl` 采集日志 | 全员、答辩合规 |
| 数据字典 | 分工表「数据字典」 | 第 6 节 8 张表 + `schema/*.json` | C、D、E 接字段 |

## 1.3 G1 门禁：已经晚了，怎么补

G1 原定 11-13（周五）交 10 种可用素材 + 授权可查。实际 11-16 入库 9 种（P01–P05、P15、P16、P17、P23），P24 龙血树因背景暖色残留判 rejected，判定为**逾期 3 天、差 1 种**，不粉饰。影响评估：D 的合成 MVP 已有 9 张可用素材，接口联调不受影响；W2 周五的 G2 仍有 2 天余量，**暂不需要启动降级**。

补救按三天闭环，每天有可验收的产物，不靠「明天多干点」：

| 日期 | 动作 | 当日产物 | 负责 |
|---|---|---|---|
| 11-15 日 | 10 种候选图定稿，写入授权行 | `inbox/` 10 组 + 授权表 10 行 | B |
| 11-16 一 | 去底、规格化、自动质检 | 9 张 PNG 入库 + `qc_report.csv` | B |
| 11-17 二 | P24 换源重做，补齐第 10 张；交 D | `assets_index.json` 10/36 | B → D |
| 11-18 三 | 36 种候选铺开，进 W2 | `inbox/` 36 组 | B |

降级触发条件写死：**若 11-17 仍不足 10 种**，按 G1 预案先交 6 种高频（龟背竹、琴叶榕、虎尾兰、绿萝、金钱树、发财树），其余回退插画，同时把 D 的合成联调从「多株」缩到「这 6 种单株」，G2 标准不变。

## 1.4 五个关键设计决策

1. **素材与评分解耦**。需求 FR-05 明确「素材不参与评分」，所以缺图只影响呈现，不阻塞 C 的评分链路。这让 B 的延期不会连带 C 延期，是排期上唯一正确的切法。
2. **百科按字段级计数**。36 种 × 8 字段 = 288 条，而不是 36 条。需求要 200–300 条，字段级才是可检索、可回源、可校对的最小单元；一条「龟背竹-浇水频率」比一篇两千字百科有用。
3. **案例按 6×5 配额采集**。30 格、每格 4 张、合计 120 张。不设配额就会采成「100 张北欧客厅」，AC-06 的 top-3 命中率也就不用测了。
4. **授权一行一张，缺一项不入库**。授权表由采集脚本强制写入，不给人肉漏填的机会；文件名、来源 URL、作者、许可、采集时间五项缺一即拒收。
5. **质检前置**。9 项自动检查 + 5 项人工目检，三态判定，fail 不入库。质检不是最后一天的抽查，是 `cutout.py` 之后必须跑的一步。

```text
├─ data/                      # 全部结构化数据（UTF-8-SIG，Excel 可直接开）

│  ├─ styles.csv / scenes.csv # 风格与场景枚举（给 C/E 的契约）
│  ├─ taxa_verified.csv       # 学名与来源链接校验结果
│  └─ assets_index.json       # 给 D 的素材可用性清单
├─ assets/
│  ├─ inbox/Pxx/              # 原始候选图（不直接上线）
│  ├─ cutout/Pxx/             # 去底成品 + 棋盘格预览
│  └─ cases/                  # 案例原图
├─ scripts/                   # 采集 → 去底 → 质检 → 索引 → 打包
├─ schema/                    # JSON Schema（asset / case / plant）
├─ logs/                      # 采集日志（jsonl，逐条可查）
└─ dist/                      # 打包产物（zip + sha256）
```

## 1.6 十分钟上手

```bash
# 1) 装依赖（首次）
python -m venv .venv && .venv\Scripts\pip install -r scripts/requirements.txt

# 2) 采集：先跑 10 种 P0，每种 1 张候选
cd scripts && python collect.py inat --plants P01,P02,P03,P04,P05,P16,P17,P23,P24,P35 --limit 1

# 3) 去底 + 规格化（≤1600px、透明底、主色回写）
python cutout.py

# 4) 质检（fail 不入库）
python qc.py --strict

# 5) 导出给 D 的索引；打包提交
python export_index.py && python package.py
```

四个数据源里，`inat` 不需要申请 Key（CC 许可，需署名），`unsplash` / `pexels` 需要免费 Key 并设置环境变量，`commons` 在能访问 Wikimedia 的网络下使用。没有 Key 也能跑通 `inat`，这是本包选择它作为兜底源的原因。
