## 权重：为什么和文档不一样

文档给的六个维度权重是 `0.22 / 0.18 / 0.18 / 0.12 / 0.15 / 0.05`，**加起来是 0.90，不是 1.00**。

如果直接拿这组数字加权，审美分满分只有 90 分，综合分天生打九折。处理方式是**按比例放大到 1.0**：

| 维度 | 文档原值 | 归一化后 |
|---|---|---|
| 色彩和谐 | 0.220 | 0.2444 |
| 形态对比 | 0.180 | 0.2000 |
| 层次比例 | 0.180 | 0.2000 |
| 质感叶面 | 0.120 | 0.1333 |
| 疏密留白 | 0.150 | 0.1667 |
| 风格一致 | 0.050 | 0.0556 |
| **合计** | **0.900** | **1.0000** |

没有把差的 0.10 补给某个维度，因为那等于凭空改了设计意图，相对比例完全不变。

综合分仍按文档：`0.68 × 审美分 + 0.32 × 适配分`。

代码里做的是**运行时归一化**（`WEIGHTS = {k: v / sum(原始值)}`），所以以后文档改权重时只改
`scoring.py` 顶部的 `WEIGHTS_RAW` 一处，不用手工算。

## 六个审美维度

| 维度 | 关键指标 | 最优区间 |
|---|---|---|
| 色彩和谐 | 绿色占比、明度跨度、中性叶株数 | 绿 55–75%、跨度 0.12–0.35、中性叶 1–2 株 |
| 形态对比 | 株型多样性、互补搭配对数、叶型种类 | ≥4 种株型、≥2 对互补、大叶+细叶都有 |
| 层次比例 | 高/中/低三层覆盖、最高与中位比、有无垂吊 | 覆盖 3 层、比值 1.8–2.5、有垂吊 |
| 质感叶面 | 质感种类数 | 3 种最佳 |
| 疏密留白 | 盆数、冠幅占空间比、株高离散度 | 3–6 株、冠幅 30–50%、CV 0.3–0.7 |
| 风格一致 | `style_tags` 命中率 | 越高越好 |

色彩用 OKLCH 而不是 HSL：HSL 的 L 是相对亮度，同样 L=50% 的黄色和蓝色人眼看着亮度差很远；
OKLCH 是感知均匀空间，L 相同就真的一样亮。需求文档指定了 OKLCH，照着实现。

## 适配分（独立维度）

| 子项 | 权重 | 规则 |
|---|---|---|
| 光照 | 0.28 | 按最挑的那株算，差 1 档扣到 75，差 ≥2 档报警 |
| 宠物 | 0.24 | 有猫狗 + `toxic=toxic` → 硬约束，每株扣 40 |
| 工时 | 0.18 | 直接用 B 的 `care_min_week` 求和 |
| 预算 | 0.16 | ≤80% 满分，超 100% 开始扣 |
| 尺度 | 0.14 | 超过 B 的 `scenes.csv` 高度上限就报警 |

**硬约束单独放 `hard_flags`，不在综合分里被平均掉**，前端按这个字段标红。

## 推荐搜索（FR-03）

### 三套方案怎么区分

不是给同一个排序换个名字，而是**换权重**：

| 性格 | 文案 | 权重调整 | 面向 |
|---|---|---|---|
| 稳妥 | 常见品种、风格统一、养护省心 | 风格一致 ×1.8、色彩和谐 ×1.2；形态对比 ×0.7 | 怕出错的人 |
| 对比 | 高低错落、大叶细叶混搭 | 形态对比 ×1.8、层次比例 ×1.6；风格一致 ×0.5 | 想要视觉张力 |
| 个性 | 冷门品种、色彩出挑 | 色彩和谐 ×1.7、质感叶面 ×1.4；风格一致 ×0.4 | 想做点不一样 |

权重调整后统一走 `normalize_weights()` 归一化，所以不管怎么调，审美分都是一百分制。

### 怎么保证三套不重复

AC-04 要求「三套方案两两 Jaccard < 0.5」。做法是每选一套就和已选的比一遍，
不满足就往下找下一个最高分的组合：

```python
for c, s in scored:                      # 按该性格的权重降序
    if all(jaccard(c, p["_combo"]) < 0.5 for p in picked):
        chosen = (c, s)
        break
```

实测客厅场景：0.400 / 0.200 / 0.167，都通过。

### 候选池怎么筛

`build_pool()` 按顺序过五道：

1. 必须有去底素材（`has_cutout`）—— 没有的放不进照片，FR-07 要求标记「仅参考」
2. 有宠物时排除 `toxic=toxic` —— AC-05 要求有毒植物 = 0
3. 光照比场景高 1 档以内 —— 差 2 档会徒长
4. 单株价格 ≤ 预算 60% —— 否则一株就超支
5. 株高 ≤ 场景上限 —— 用 B 的 `scenes.csv` 区间

### 枚举策略

按株高分三层（≥100cm / 40–100 / <40），枚举「1 高 + 1~2 中 + 1~2 低」，
各层取前几个控制组合数在几百量级。

小空间有坑：**办公桌的高度区间只有 8~50cm，根本不存在「高」层**，
照原结构枚举会得 0 个组合。所以做了逐层 fallback：
没高层就把中层最高的提上来，没中层就把低层提上来，还是不行就只枚举两株。

### 性能

六个维度只算一次（`score_combo`），三种性格换权重时只重算加权（`rescore`）。
实测客厅场景（151 个组合 × 3 种性格）**0.03 秒**，远低于 FR-03 的 P95 < 2s。

不这么做的话，480 个组合 × 3 种性格全量重算要 1.4 秒左右。

## 改稿逻辑（FR-08）

### 七种指令

全部靠关键词匹配，不依赖 LLM，所以断网也能演示（对应 AC-10「无 Key 可完整演示」）。

| 指令 | 关键词举例 | 类型 | 做什么 |
|---|---|---|---|
| 更好养 | 好养、省心、懒人、皮实 | 过滤 | 换成 `difficulty=易` 且 `care_min_week ≤ 15` 的 |
| 对猫狗安全 | 猫、狗、宠物、无毒 | 过滤 | 换成 `pet_safe=true` 且 `toxic≠toxic` 的 |
| 预算降一档 | 预算、便宜、省钱 | 过滤 | 换贵的，单株价压到目标总价的 1/3 以内 |
| 再矮一点 | 矮、低一点、太高 | 过滤 | 把最高的换成不超过原最高 80% 的 |
| 更有张力 | 张力、冲击、出片、好看 | 增强 | 找一株最能提升「形态对比」的换进去 |
| 加一点垂坠 | 垂坠、藤、垂下来 | 新增 | 补一株垂吊，或把非垂吊的换成垂吊 |
| 更安静 | 安静、素、简约、干净 | 调权重 | 不换植物，把评分口径调向层次和留白 |

### 保留率 >= 50% 怎么保证

FR-08 的验收要求「过滤类改稿保留原方案 >= 50%」，所以**最多只能换一半**：

```python
max_change = max(1, len(original) // 2)   # 3 株换 1 株，4 株换 2 株
scored = [(p, _penalty(p, intent, scene)) for p in original]
bad = [x for x in scored if x[1] > 0]
bad.sort(key=lambda x: -x[1])             # 最差的先换
to_replace = bad[:max_change]
```

如果原方案里有超过一半的植物不合格，就只换最差的几株，`satisfied=False` 并在 note 里
如实说明「改后仍有 N 株不满足」。**宁可告知，也不偷偷全换掉。**

### 为什么「更好养」会掉分

实测基础方案（93.0 分）改成「更好养」后掉到 84.0。这是正常的——
好看和好养本来就有张力，把养护时间压缩，通常会牺牲形态和色彩的变化度。
这个分数变化本身就是有价值的信息，前端可以把 `score_delta` 展示出来，让用户自己权衡。

### 实测效果

| 指令 | 换出 → 换入 | 分数变化 | 保留率 |
|---|---|---|---|
| 更好养 | 孔雀竹芋 → 莺萝兰 | 92.4 → 84.0（-8.4） | 67% |
| 对猫狗安全 | 无需更换 | 92.4 → 92.4 | 100% |
| 预算降一档 | 发财树 → 栀子 | 92.4 → 80.3（-12.1） | 67% |
| 再矮一点 | 发财树 → 青苹果竹芋 | 92.4 → 82.5（-9.9） | 67% |
| 更有张力 | 孔雀竹芋 → 鹿角蕨 | 92.4 → **94.8（+2.4）** | 67% |
| 加一点垂坠 | 已有垂吊，提示不重复加 | 不变 | 100% |
| 更安静 | 不换植物，只调权重 | 92.4 → 93.3（+0.9） | 100% |

只有「更有张力」是加分改稿，因为它换进来的鹿角蕨补上了「附生」这个株型，
形态对比 +12 分。其余过滤类改稿都会掉分，符合预期。

## 案例检索（FR-09）

### 为什么用 ResNet50 而不是 CLIP

需求写的是 CLIP，但本机没装 `transformers` / `open_clip`，装一个要下 350MB 权重。
而 torchvision 的五个预训练模型权重本地**全都有**，一个字节都不用下载：

```
resnet18-f37072fd.pth            44.7 MB
resnet50-11ad3fa6.pth            97.8 MB
efficientnet_b0                  20.5 MB
mobilenet_v3_large               21.1 MB
convnext_tiny                   109.1 MB
```

差别在哪：CLIP 是图文对齐的，可以用「暖色调客厅」这样的**文本**搜图；
ResNet50 只做图像特征，只能「以图搜图」和按标签筛。
FR-09 要的核心能力是「找相似」，ResNet50 够用——实测 top-3 命中率 100%。

`ImageEmbedder(backbone=...)` 留了扩展位，以后装了 open_clip 加一个分支就行，
上层 `CaseIndex` 一行都不用改。

### 一个坑：torchvision 会偷偷重下权重

torchvision 新版按**不同的 hash** 找权重：要 `resnet50-0676ba61`，而本地缓存的是
`resnet50-11ad3fa6`。直接 `models.resnet50(weights=DEFAULT)` 会触发 97MB 重下载，
当前网速 50KB/s 要半小时。

所以代码里一律用 `weights=None` 构造 + `load_state_dict` 手动灌本地权重：

```python
net = builder(weights=None)
state = torch.load(weight_path, map_location="cpu", weights_only=True)
net.load_state_dict(state)
```

## 风格分类基线

对应需求里的「CLIP 选型与评测方案 + 风格分类基线（top-1）」。
没有 CLIP，用 ResNet50 特征 + 逻辑回归先立个基线，把「top-1 准确率」这个指标做出来。

**样本**：B 的案例库去重后 110 条，6 类（北欧 20 / 中古 20 / 热带 19 / 工业 19 / 日式 18 / 极简 14）

**方法**：5 折分层交叉验证。不用单次 70/30 划分——110 条上抖得太厉害。

**结果**：

| 指标 | 数值 |
|---|---|
| top-1 准确率 | **40.0%** |
| 多数类基线（全猜北欧） | 18.2% |
| 随机基线 | 16.7% |
| 比多数类高 | **+21.8 个百分点** |

各类 F1：日式 0.476 / 北欧 0.455 / 中古 0.444 / 工业 0.381 / 热带 0.343 / 极简 0.190

**怎么看这个 40%**：

1. **6 类分类 40% 是有意义的**——随机是 16.7%，翻了一倍多。
2. **但不算好**。原因有三个：样本只有 110 条；ResNet50 训的是 ImageNet 物体分类，
   对「室内风格」这种抽象语义不敏感；北欧和极简在视觉上本来就相近（混淆矩阵里这两类互串最多）。
3. **这正好说明为什么需要 CLIP**。CLIP 在图文对齐的语义空间里，对「北欧」「侘寂」
   这类风格词更敏感。换上 CLIP 特征后重跑 `evaluate()` 就能对比，
   评估代码一行都不用改——这就是把特征提取器做成可替换的原因。

**答辩时怎么说**：「我们用 ResNet50 特征训了个基线，6 类 top-1 是 40%，比随机高 24 个百分点。
这个数字不高，主要受限于样本量和特征语义粒度，所以我们把 CLIP 列为下一步升级方向，
评估框架已经搭好了，换特征就能验证。」

## 对 B 的数据依赖

### 已解决（v1.7，2026-11-18）

v1.6 的 `plants_master.csv` 缺两个评分要用的字段，只能从 `leaf` 描述和 `morphology`
文本里硬推，准确度很差。v1.7 补上了：

| 字段 | v1.6 我的派生 | v1.7 B 给的 |
|---|---|---|
| `leaf_size` | 中叶 39/48（81% 挤在一类） | 细叶 20 / 中叶 16 / 大叶 12（均衡） |
| `texture` | 哑光 38/48（79% 是默认值） | 光泽 22 / 纸质 10 / 革质 9 / 绒面 4 / 哑光 3 |

两者的**一致率只有 58%（叶型）和 17%（质感）**，可见派生只能当兜底。

`loader.py` 现在是「有列就用列，没列才派生」，所以 v1.6 和 v1.7 都能跑：

```python
leaf_size = (row.get("leaf_size") or "").strip()
if leaf_size not in LEAF_SIZES:
    leaf_size = _parse_leaf_size(leaf)      # 旧数据兜底
```

**换数据后评分变好了**（同一场景、同一权重）：

| 方案 | v1.6 派生 | v1.7 B 给 |
|---|---|---|
| 稳妥 | 93.0 | **95.9** |
| 对比 | 91.0 | 91.9 |
| 个性 | 90.1 | 92.9 |
| 对比 vs 个性 的 Jaccard | 0.167 | **0.000** |

提升主要来自质感维度——v1.6 里 79% 的植物都是「哑光」，这一维基本恒定为 72 分；
v1.7 有了 5 种真质感，三套方案的质感分都能打到 100。

## 已知的设计取舍

1. **绿色占比 100% 不给 0 分**：早期版本按「偏离 55–75% 就猛扣」算，正常的绿植组合被打到 37 分。
   现在绿色过多只算「单调」，扣得轻（100% 全绿约 70 分）。
2. **明度跨度用 0.12–0.35**：文档没给区间，按 B 数据里叶色的实际分布定。
   早期照搬色彩学的 0.25–0.45，结果所有组合都被扣分。
3. **视觉重量用株高离散度代理**：文档写「左右视觉重量」，但评分引擎只拿到植物列表、没有画布坐标，
   用株高的变异系数近似。等 E 的画布把坐标传过来可以换成真实比例。
4. **株高取区间中值**：B 的 `height_min_cm` / `height_max_cm` 是区间，评分时取中值，
   实际合成时应该用用户选定的目标高度。
