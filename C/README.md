## 当前交付内容

七维评分引擎：输入一组植物和用户场景，输出六个审美维度分、一个适配分、综合分，
外加能指着具体植物说的理由。这是 C 角色 W1–W2 的核心交付（七维评分设计 + 实现 + 单测）。

```
C/
├── verda/
│   ├── color.py     OKLCH 色彩工具（sRGB ↔ OKLab ↔ OKLCH）
│   ├── models.py    Plant / Scene / Combo / DimensionScore / ComboScore
│   ├── loader.py    读 B/data 的 plants_master.csv 和 assets_index.json
│   └── scoring.py   七维评分主逻辑
├── demo.py          用 B 的真实数据跑四套方案
└── test_scoring.py  24 个单测
```

## 怎么跑

在仓库根目录（`B/` 和 `C/` 的上一层）：

```bash
python C/demo.py
python -m unittest C.test_scoring -v
```

或者进到 `C/`：


## 权重：为什么和文档不一样

文档给的六个维度权重是 `0.22 / 0.18 / 0.18 / 0.12 / 0.15 / 0.05`，**加起来是 0.90，不是 1.00**。

如果直接拿这组数字加权，审美分满分只有 90 分，综合分天生打九折。处理方式是**按比例放大到 1.0**：

| 维度 | 文档原值 | 归一化后 |
|---|---|---|
| 色彩和谐 | 0.220 | 0.2444 |
| 形态对比 | 0.180 | 0.2000 |
| 层次比例 | 0.180 | 0.2000 |
| 质感叶面 | 0.120 | 0.1333 |
| 疏密留白 | 0.150 | 0.1667 |
| 风格一致 | 0.050 | 0.0556 |
| **合计** | **0.900** | **1.0000** |

没有把差的 0.10 补给某个维度，因为那等于凭空改了设计意图，相对比例完全不变。

综合分仍按文档：`0.68 × 审美分 + 0.32 × 适配分`。

代码里做的是**运行时归一化**（`WEIGHTS = {k: v / sum(原始值)}`），所以以后文档改权重时只改
`scoring.py` 顶部的 `WEIGHTS_RAW` 一处，不用手工算。

## 六个审美维度

| 维度 | 关键指标 | 最优区间 |
|---|---|---|
| 色彩和谐 | 绿色占比、明度跨度、中性叶株数 | 绿 55–75%、跨度 0.12–0.35、中性叶 1–2 株 |
| 形态对比 | 株型多样性、互补搭配对数、叶型种类 | ≥4 种株型、≥2 对互补、大叶+细叶都有 |
| 层次比例 | 高/中/低三层覆盖、最高与中位比、有无垂吊 | 覆盖 3 层、比值 1.8–2.5、有垂吊 |
| 质感叶面 | 质感种类数 | 3 种最佳 |
| 疏密留白 | 盆数、冠幅占空间比、株高离散度 | 3–6 株、冠幅 30–50%、CV 0.3–0.7 |
| 风格一致 | `style_tags` 命中率 | 越高越好 |

色彩用 OKLCH 而不是 HSL：HSL 的 L 是相对亮度，同样 L=50% 的黄色和蓝色人眼看着亮度差很远；
OKLCH 是感知均匀空间，L 相同就真的一样亮。需求文档指定了 OKLCH，照着实现。

## 适配分（独立维度）

| 子项 | 权重 | 规则 |
|---|---|---|
| 光照 | 0.28 | 按最挑的那株算，差 1 档扣到 75，差 ≥2 档报警 |
| 宠物 | 0.24 | 有猫狗 + `toxic=toxic` → 硬约束，每株扣 40 |
| 工时 | 0.18 | 直接用 B 的 `care_min_week` 求和 |
| 预算 | 0.16 | ≤80% 满分，超 100% 开始扣 |
| 尺度 | 0.14 | 超过 B 的 `scenes.csv` 高度上限就报警 |

**硬约束单独放 `hard_flags`，不在综合分里被平均掉**，前端按这个字段标红。

| 字段 | 类型 | 说明 |
|---|---|---|
| `aesthetic` / `fit` / `total` | float | 0–100，一位小数 |
| `hard_flags` | string[] | 硬约束提示，空数组表示没有 |
| `reasons` | string[] | 3–4 条 |
| `dimensions[]` | object[] | 六条，顺序固定（色彩→形态→层次→质感→疏密→风格） |
| `dimensions[].weight` | float | 归一化后，六个加起来是 1.0 |
| `dimensions[].contribution` | float | `score × weight`，画堆叠条用 |

## 对 B 的数据需求

现在 `plants_master.csv` 里，评分需要的两个字段**没有**，只能从 `leaf` 描述和 `morphology`
文本里推，准确度有限：

| 字段 | 现在怎么来的 | 问题 | 建议 |
|---|---|---|---|
| `leaf_size` | 从 `leaf` 推（"大叶深裂"→大叶） | 「心形/披针/掌状」这类讲的是叶形不是大小，48 种里 39 种判成中叶 | 建议直接加一列 `leaf_size`，取值 大叶/中叶/细叶 |
| `texture` | 从 `leaf` + `morphology` 关键词推 | 关键词命中率低，48 种里 38 种落到默认「哑光」 | 建议加一列 `texture`，取值 光泽/哑光/绒面/纸质/革质 |

`dominant_hex`、`light_level`、`toxic`、`pet_safe`、`style_tags`、`scene_tags`、
`care_min_week`、`height_min/max_cm`、`spread_cm`、`price_cny` 这些 B 都给了，直接用，没问题。

在 B 补列之前，`_score_texture` 对「全组都是哑光」的情况给 72 分而不是 50 分，
因为那更可能是数据没标注，而不是真的单调。

## 已知的设计取舍

1. **绿色占比 100% 不给 0 分**：早期版本按「偏离 55–75% 就猛扣」算，正常的绿植组合被打到 37 分。
   现在绿色过多只算「单调」，扣得轻（100% 全绿约 70 分）。
2. **明度跨度用 0.12–0.35**：文档没给区间，按 B 数据里叶色的实际分布定。
   早期照搬色彩学的 0.25–0.45，结果所有组合都被扣分。
3. **视觉重量用株高离散度代理**：文档写「左右视觉重量」，但评分引擎只拿到植物列表、没有画布坐标，
   用株高的变异系数近似。等 E 的画布把坐标传过来可以换成真实比例。
4. **株高取区间中值**：B 的 `height_min_cm` / `height_max_cm` 是区间，评分时取中值，
   实际合成时应该用用户选定的目标高度。
