## 4 五个实现决定

1. **坐标统一用照片像素**，不用屏幕坐标；缩放只影响显示。前端预览与服务端合成因此永远同一套几何。
2. **拖动本地即时、合成服务端异步**：拖动只改 DOM 图层（不卡），松手再请求合成。观感是实时的，但像素级合成、阴影、水印仍由服务端负责，不越界替 D 拍板合成质量。
3. **落地线取平均高度**：`/api/compose` 只收一个 `ground_y`；倾斜 >3° 时在锚定提示里明确写「按平均高度落地」，不假装支持透视。
4. **层级 `layer` 越小越靠前**（0 最前），与 `docs/14` 第 8 节一致；「已放植物」的 ↑↓ 改的就是这个值。
5. **植物可自由摆放**：左右沿落地线移动，上下可抬升（显示「离地 X cm」，靠地 8px 内自动吸附回地面），拖动不改变大小。
   ⚠️ **限制**：`/api/compose` 的 items 只有 `x`，落地基准 y 是整条线一个值。所以只要有植物离地，预览与导出都改走**前端 canvas 合成**（服务端只负责全部贴地的情况）。要把离地摆放交给服务端，需要 D 在 items 里加 `y` 字段。
6. **株高在品种区间内选规格**（默认中位数），不允许自由缩放。⚠️ 请 A 确认是否算违反 FR-07「高度锁定真实株高」；若算，删掉 `hRange` 滑块即可（一处改动）。

## 6 部署（暂停，恢复时按此执行）

拓扑：`2C4G ECS → nginx :80 → 静态 frontend/ + 反代 /api 到 gunicorn(127.0.0.1:8000) → Flask`；`assets/` 由 nginx 直接出，不进 Python worker（否则 50MB 素材会占满 worker）。

要点：安全组只开 80/443 与自己的 IP；venv + `pip install -r requirements.txt`；`systemd` 起 gunicorn；nginx 对 `/assets/` 开 `expires 7d`、对 `/api/` 关缓存。手册落到 `docs/16_部署手册.md`，恢复后第一天先让 D 照着跑一遍（分工表点名的单点风险：E 同时承担画布与部署）。
