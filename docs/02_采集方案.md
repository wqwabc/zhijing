# 2 采集方案：四个源、六步链路、一套命名

## 2.1 资产与来源矩阵

课程第 2 条要的是「多源多模态采集」，落在 B 身上是三类数据、四种模态。矩阵里每一行都写清目标量、首选源和备选源，避免临场找图。

| 资产 | 模态 | 目标量 | 首选源 | 备选源 | 优先级 |
|---|---|---|---|---|---|
| 植物属性 | 结构化 | 48 种 × 31 字段 | 百科 + 人工核对 | 植物智、园艺站 | P0 |
| 植物去底素材 | 图像 | 48 张（长边≥1200、带 alpha） | Unsplash / Pexels | Wikimedia、iNaturalist、自摄 | P0 |
| 装饰案例 | 图像 + 标签 | 120 张（6×5 配额） | Unsplash / Pexels | Wikimedia、iNaturalist | P1 |
| 百科文本 | 文本 | 384 条字段记录 | Wikipedia API | 植物智、iNaturalist 分类页 | P0 |
| 搭配原则 | 文本 | 22 条 | 课程整理 + 案例归纳 | — | P0 |
| 痛点样本 | 文本 | 200 条 | 公开评论/问答 | — | P1 |

来源数：Unsplash、Pexels、Wikimedia、iNaturalist 共 4 个平台，满足「来源 ≥ 3 个平台」；模态上图像（素材/案例/用户照片）+ 文本（百科/原则/痛点）满足「≥ 2 种」。

## 2.2 白名单与准入门槛

| 源 | 许可 | 可商用 | 必须署名 | 允许改作 | 采集方式 |
|---|---|---|---|---|---|
| Unsplash | Unsplash License | 是 | 不强制（建议） | 是 | 官方 API，需 Access Key |
| Pexels | Pexels License | 是 | 不强制（建议） | 是 | 官方 API，需 Key |
| Wikimedia Commons | CC0 / CC BY / CC BY-SA | 视许可 | CC BY 系必须 | 视许可 | MediaWiki API |
| iNaturalist | CC0 / CC BY / CC BY-NC 系 | 视许可（NC 仅非商业） | 必须 | 视许可 | 开放 API，无需 Key |

三条硬规则：

1. **NC 许可只用于课程作业与非商业演示**，页面与文档标注「非商业用途」，答辩被问到时直说，不含糊。
2. **不采**小红书、淘宝、京东、宜家官网的图进演示材料。宜家图只做离线统计（分工表已约定），不进 `assets/`。
3. **AI 生成图不进素材库**。需求第 9 节明确不做生成式「画」植物，素材必须是实拍去底，这条没有例外。

## 2.3 六步链路

```text
① 候选采集  collect.py    → assets/inbox/Pxx/ + _candidates.jsonl + 授权行
② 授权核验  license_table → 五项齐全才允许进入下一步
③ 去底      cutout.py     → rembg / 纯色泛洪，输出 RGBA
④ 规格化    cutout.py     → 裁边、留 1.5% 边距、长边 ≤1600（不放大）、命名
⑤ 质检      qc.py         → 9 项自动 + 5 项目检，fail 退回 ③
⑥ 入库      export_index  → assets_index.json + 清单状态置 ready
```

第 ② 步是强制的：`collect.py` 每下载一张就写一行授权，`qc.py` 再反查该行是否存在。跳过 ② 直接 ③ 的图，在 ⑤ 会被判 fail——这是把合规做进流程，而不是靠自觉。

## 2.4 去底的三条路线

| 路线 | 工具 | 单张耗时 | 质量 | 适用 |
|---|---|---|---|---|
| 本地批量 | onnxruntime + u2net（rembg 同款模型） | 1–3s（CPU） | 叶片边缘干净，细叶仍会断 | 48 张主力方案 |
| 在线 API | remove.bg | 1–3s | 最好，细叶与半透明处理稳 | 返工与重点图 |
| 手工 | Photoshop 钢笔/蒙版 | 10–20min | 可控 | 答辩主视觉 3–5 张 |

工程上采用「u2net 全量 + `--harden` 压阴影 + 手工返工 top5」：先把 48 张过一遍，`--harden` 把 alpha 拉成近似二值，专门对付白墙上的投影与半透明灰边；`qc.py` 再挑出 `component < 0.8`（细叶断裂）与 `border_alpha > 0.1`（背景没去净）的图，用在线 API 或手工救。**不追求每张完美，追求每张可判定**。

修边三条规则：

- **毛边**：alpha 边缘 1–2px 的半透明残留，用「收缩 1px + 羽化 0.5px」处理，不要直接二值化，否则叶缘发硬。
- **色边**：背景色溢出到叶缘（常见于白底转透明），用「去色溢出」把边缘像素向叶色拉，肉眼看不到白边为准。
- **断叶**：细叶（文竹、蕨类）断成多块时，`component` 会掉到 0.6 以下，直接换源图，不要用膨胀硬连——连出来的叶子是假的。

## 2.5 命名与目录

```text
assets/inbox/P01/P01_inat_3f9a2c11.jpg          # 原始候选（sha1 前 8 位防重）
assets/cutout/P01/P01_front_inat.png            # 成品：{plantId}_{view}_{source}.png

assets/cases/nordic_living_001.jpg              # 案例：{style}_{room}_{序号}.jpg
```

命名规则来自分工表第 10 节：`{plantId}_{view}_{source}.png`。`view` 目前只有 `front`，后续若补 45° 或俯视，加 `side45` / `top` 即可，不用改目录结构。

## 2.6 断点续采与幂等

采集最怕两件事：跑一半断了要重来、重复下载把磁盘塞满。`collect.py` 用三个机制解决：

- **内容去重**：按 sha1 前 8 位命名，同图重复下载直接命中已有文件，不写第二次。
- **授权去重**：`(file_name, source_url)` 作为唯一键，重复运行不会在授权表里堆重复行。
- **日志追加**：每次下载写一行 `logs/collect_YYYYMMDD.jsonl`，含时间、植物、来源、文件、许可。断了看日志就知道停在哪，加 `--plants P07` 接着跑即可。

限速与礼貌：iNat 每次请求间隔 0.25–0.3s，单植物最多 30 条候选，不做并发轰炸；Unsplash/Pexels 遵守 50 次/小时的免费额度，批量前先 `--dry-run` 看命中率再决定 `--limit`。
