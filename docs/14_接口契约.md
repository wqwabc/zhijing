## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 开发 `http://127.0.0.1:5000`；部署 `https://<华为云域名>`（nginx + gunicorn） |
| 编码 | 请求与响应一律 UTF-8 JSON（文件上传除外，multipart/form-data） |
| 版本标识 | 响应头 `X-Verda-API-Version: 1` |
| 鉴权 | MVP 无鉴权；演示环境由 nginx 层限制（部署时加） |
| 照片留存 | 仅存内存与临时目录，会话过期即删（FR-01 合规要求：不长期存储、不外传） |
| LLM | Agent 九步（W3）默认无 Key 兜底，接口行为与有 Key 时一致（AC-10） |
| 跨域 | 默认允许全部来源（开发期）；生产用环境变量 `VERDA_CORS_ORIGINS` 收敛为逗号分隔白名单 |
| 请求体上限 | 11MB（照片 10MB + multipart 余量），超出直接 413，不解析内容 |

错误响应统一结构（HTTP 状态码非 2xx 时）：

```json
{
  "error": {
    "code": "E40003",
    "message": "照片过暗，平均亮度 21/255，低于阈值 40",
    "hint": "建议面向窗户重拍，或改用立面模式",
    "field": "photo"
  }
}
```

错误码表：

| code | HTTP | 含义 | 典型场景 |
|---|---|---|---|
| E40001 | 400 | 参数缺失或类型错误 | plant_ids 为空、坐标越界 |
| E40002 | 415 | 照片格式不支持 | 非 JPG/PNG，或 >10MB |
| E40002 | 413 | 请求体超过上限 | 整个 multipart 超过 11MB，在解析前拒掉 |
| E40003 | 422 | 照片校验不通过 | 模糊/过暗/过曝/无地面/分辨率不足 |
| E40401 | 404 | photo_id 不存在或已过期 | 会话超时（当前 30 分钟） |
| E40402 | 404 | plant_id 不在主数据里 | 前端传了错 id |
| E40403 | 404 | 素材文件缺失 | 索引里有、磁盘上没有 |
| E40901 | 409 | 合成参数矛盾 | px_per_cm 超出合理范围 |
| E50001 | 500 | 服务端内部错误 | 合成异常等，附带 request_id 便于排查 |

## 3. POST /api/upload（FR-01）

请求：`multipart/form-data`，字段 `photo`（JPG/PNG，≤10MB，长边 ≥1200px）。

```json
{
  "photo_id": "ph_8f3a1c",
  "width": 3024,
  "height": 4032,
  "checks": [
    {"name": "resolution",  "pass": true,  "message": "长边 4032px ≥ 1200px"},
    {"name": "blur",        "pass": true,  "message": "清晰度 186.4（阈值 60）"},
    {"name": "brightness",  "pass": true,  "message": "平均亮度 118/255"},
    {"name": "exposure",    "pass": true,  "message": "过曝像素占比 0.4%"},
    {"name": "ground",      "pass": true,  "message": "画面下部检测到地面区域"}
  ],
  "usable": true,
  "warnings": [],
  "suggestion": ""
}
```

规则：

- 任何一项 `pass=false` → `usable=false`，附 `suggestion`（重拍建议）。
- 模糊/过暗/过曝/无地面为**阻断项**；轻则给 `warnings`（不阻断）。
- `usable=false` 时前端引导「改用立面模式」（降级路径），**不阻断流程**。
- 照片只进内存/临时目录，`photo_id` 30 分钟过期自动删除。

## 4. POST /api/anchor（FR-02）

请求：

```json
{
  "photo_id": "ph_8f3a1c",
  "ground":  [{"x": 120, "y": 3510}, {"x": 2800, "y": 3460}],
  "ref":     [{"x": 2890, "y": 3470}, {"x": 2905, "y": 980}],
  "ref_type": "door",
  "custom_height_cm": null
}
```

- `ground`：用户点两下画的地面线（图像像素坐标，原点左上）。
- `ref`：跨高度参照的两点（如门底到门顶）；`ref_type` ∈ `door|bed|sofa|custom`，默认高度 200 / 50 / 80 cm，`custom` 必填 `custom_height_cm`。
- 全流程 ≤3 步（画地面线 → 画参照 → 选类型），满足 AC-02。

响应：

```json
{
  "px_per_cm": 6.24,
  "ref_height_cm": 200,
  "ground_y_mid": 3485,
  "ground_y": 3485,
  "ground_angle_deg": -1.02,
  "ref_length_px": 1248.6,
  "warnings": [],
  "preview": {"suggest_plant": "P01", "suggest_height_cm": 150,
              "suggest_px": 936}
}
```

- `ground_y_mid`：地面线两点的中点 y；`ground_y` 是同值的别名，**直接透传给 /api/compose 即可**，不需要前端改名。
- 地面有透视时（`ground_angle_deg` 明显非 0），前端应按 `ground_line` 在每株的 x 处插值出各自的 `ground_y`，这时两点不等高，插值结果比中点更准。

- `px_per_cm = ref_length_px / ref_height_cm`；超出 `[0.5, 40]` 判定锚定失败（E40901）。
- 高度参照线接近水平（垂直分量小于线长的 20%）返回 E40001，需重新沿竖直方向点选。
- `preview`：建议放一株 150cm 参照物（FR-02 的实时预览校验），`suggest_px` 即该株的像素高度。

## 5. POST /api/score（FR-03/06/07，双入口同一口径）

请求：

```json
{
  "plant_ids": ["P01", "P05", "P04"],
  "scene": {"room": "living", "style": "nordic", "light": 2,
             "weekly_minutes": 30, "has_pet": true, "budget": 400}
}
```

响应 = C 的 `score_combo(...).as_dict()` **原样**（字段不重定义，见 docs/13）：

```json
{
  "aesthetic": 79.1,
  "fit": 67.6,
  "total": 75.4,
  "hard_flags": ["家里有宠物，但含 3 株有毒植物：琴叶榕、绿萝、虎尾兰"],
  "reasons": ["「琴叶榕」高 150cm，撑起竖向主景，……"],
  "dimensions": [
    {"name": "色彩和谐", "score": 80.5, "weight": 0.2444,
     "contribution": 19.68, "detail": "绿色基调 100%，明度跨度 0.27，中性叶 0 株"}
  ]
}
```

- `dimensions` 固定六条，顺序：色彩 → 形态 → 层次 → 质感 → 疏密 → 风格。
- 双入口（推荐/自选）都走本接口，**保证 AC-11 分数一致**。
- 性能目标：P95 < 0.5s。

## 8. POST /api/compose（FR-04，核心）

请求：

```json
{
  "photo_id": "ph_8f3a1c",
  "anchor": {"px_per_cm": 6.24, "ground_y": 3485},
  "items": [
    {"plant_id": "P01", "x": 1450, "height_cm": 150, "layer": 0}
  ],
  "watermark": true
}
```

| 字段 | 说明 |
|---|---|
| `anchor.px_per_cm` | /api/anchor 的结果；缺失时返回 E40001 |
| `anchor.ground_y` | 落地基准线，须在 `(0, 照片高度]` 内；可由前端按 ground_line 在 x 处插值 |
| `items[].plant_id` | 必须在素材清单里且 `available=true`，否则 E40402/E40403 |
| `items[].x` | 落地点横坐标（像素，指植物中轴线），须在 `[0, 照片宽度]` 内。越界返回 E40001；贴边时后端会把整株夹回画布内（不裁切），并在 `items_meta[].clipped` 标记 |
| `items[].height_cm` | 目标株高。**默认取素材索引 `height_range_cm` 中值**；超出真实区间时夹回并附 warning（FR-07） |
| `items[].layer` | 非负整数层级，0 为最前；同层级按输入顺序绘制 |
| `watermark` | 默认 true：右下角标「效果示意」（合规要求） |

约束：`items` 1–6 株（FR-07 自选上限 6；G2 门禁为 3 株同屏）。超出返回 E40001。
坐标、株高和比例必须是有限 JSON 数字；类型错误或坐标越界返回 E40001。照片校验元数据缺失时返回 E40401，需重新上传。

响应：

```json
{
  "image_url": "/api/compose/so_9d2f01.png",
  "width": 3024,
  "height": 4032,
  "items_meta": [
    {"plant_id": "P01", "name_cn": "龟背竹", "kind": "photo",
     "drawn_height_px": 936, "requested_height_cm": 150,
     "actual_height_cm": 150, "x_actual": 1450, "clipped": false,
     "layer": 0, "bbox": [1210, 2549, 1690, 3485]}
  ],
  "elapsed_ms": 812,
  "expires_at": "2026-11-21T18:00:00+08:00"
}
```

- 合成图放临时目录，随 `photo_id` 一起过期删除；`expires_at` 同步给前端。
- `items_meta[].x_actual` 是实际绘制的中轴线 x（被夹回画布后的值）；`clipped=true` 表示请求位置贴边、后端把整株平移进了画布，前端若要「拖到哪就画到哪」应据此提示。
- `drawn_height_px` 是素材可见区域（含花盆）的绘制高度；`actual_height_cm` 是请求株高夹回真实区间后的值。花盆占比尚未从素材中扣除，株高口径以 A 的验收标准为准（待 B 补 `pot_ratio`）。
- `kind` 标注 `photo|illustration`：**绝不用插画冒充实拍**，前端需在清单中展示该标注（素材索引暂无此字段，由后端按文件路径 `assets/illustrations/` 推导，B 补字段后切换）。
- 性能目标：P95 < 3s（1080p，CPU）；当前实现含等比缩放、贴地、柔和接触阴影、层级排序；色温匹配 W2 交付。

## 9. GET /api/plants（FR-07 自选面板）

响应（列表，48 条）：

```json
{
  "count": 48,
  "plants": [
    {"plant_id": "P01", "name_cn": "龟背竹", "name_latin": "Monstera deliciosa",
     "height_range_cm": [80, 180], "spread_cm": 80,
     "difficulty": "易", "price_cny": "80-200",
     "tags": ["大叶", "耐阴", "有毒"],
     "available": true, "kind": "photo",
     "thumb_url": "/api/assets/P01/thumb",
     "image_url": "/api/assets/P01/image",
     "style_tags": ["tropical", "minimal"],
     "pet_safe": false, "toxic": "toxic"}
  ]
}
```

- `available=false` 的植物前端灰显为「仅参考」（FR-07 素材可用性）。
- 面板请用 `thumb_url`（256px 高、WebP、约 15KB），原图单张 900KB；48 张面板若全用 `image_url` 首屏要拉 40MB+，点选 <200ms 必然不达标。
- `tags` 派生规则：`leaf_size`、光照 L1/L2 → `耐阴`、`form=垂吊` → `垂吊`、`pet_safe` → `宠物友好`、`toxic=toxic` → `有毒`。
- 支持查询参数过滤：`?tag=宠物友好&search=榕&available=true`（W2 实现，结构先行冻结）。

## 10. GET /api/assets（FR-05）

响应（带 ETag，304 缓存；数据源 `data/assets_index.json`）：

```json
{
  "schema": "verda.assets.index/1.0",
  "count": {"total": 48, "available": 48, "photo": 25, "illustration": 23},
  "items": [
    {"plant_id": "P01", "name_cn": "龟背竹", "available": true,
     "kind": "photo", "width": 1177, "height": 1600,
     "height_range_cm": [80, 180], "dominant_hex": "#2A2E26",
     "thumb_url": "/api/assets/P01/thumb",
     "image_url": "/api/assets/P01/image"}
  ]
}
```

- `kind` 由后端按文件路径推导（photo / illustration），并修正索引里的反斜杠路径（P45、P48，已提给 B）。
- 响应头 `ETag` 基于索引文件 sha256；前端与 nginx 可长缓存。

## 11. GET /api/assets/{plant_id}/image

- 200：PNG（去底原图或插画），`Content-Type: image/png`，带 `Cache-Control: public, max-age=86400`。
- 404（E40402/E40403）：id 不存在或文件缺失。

## 11.1 GET /api/assets/{plant_id}/thumb

- 200：256px 高缩略图，按 alpha 裁掉透明边，WebP（`image/webp`，约 10–20KB）；Pillow 未编 WebP 时退回 PNG。
- 首次请求生成并落盘到仓库 `.cache/thumbs/`（该目录已在 `.gitignore`，不上传）；此后直接命中缓存。
- 响应头 `Cache-Control: public, max-age=86400`。
- 404（E40402/E40403）：id 不存在或文件缺失。

## 13. 性能与降级预算（汇总）

| 接口 | 目标 | 降级策略 |
|---|---|---|
| /api/upload | < 1s | 不限格式，仅校验五项 |
| /api/anchor | < 100ms | 纯几何计算 |
| /api/score | P95 < 0.5s | 纯标准库，无外部依赖 |
| /api/recommend | P95 < 2s | degraded=true 时只回 error |
| /api/compose | P95 < 3s @1080p | 限制株数；预缩放素材缓存 |
| 无 LLM Key | — | Agent 各步走规则兜底，接口结构不变（AC-10） |
| 照片校验失败 | — | 回退立面模式 + 案例图，主链路不断 |
