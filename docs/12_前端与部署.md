## 2 三个观察点：怎么判定「它真的能跑」


## 3 四个关键决策（其中两个需要 A 确认）

1. **像素每米由前端算、随请求送给后端**。地面线两点 + 参照物两点 → `px_per_m`，合成接口直接收这个值。理由：它依赖用户照片的屏幕坐标，服务端重算反而多一次误差来源。
2. **素材代表株高取 `height_range_cm` 中位数**（遵循 `docs/06` 6.3 节）。⚠️ 待确认：这意味着「同一张素材永远代表该品种的中等株」，如果 B 后续补了逐张真实株高，这里要改成读 `plant_height_cm`。
3. **透明边距自动检测**：素材 PNG 四周有透明留白，直接按图片高度缩放会让植物偏小且“悬空”。所以加载时扫一遍 alpha 包围盒，按**视觉底部**贴地、按视觉高度缩放（`bboxOf()`）。这是 AC-03「无悬浮感」能达标的前提之一。
4. **株高允许在品种区间内选规格，不允许鼠标自由缩放**。口径：面板里点进来默认中位数，图层里用滑块在 `[height_min_cm, height_max_cm]` 内选 80/120/150 这类市售规格。**请 A 确认这算不算违反 FR-07「高度锁定真实株高」**；若判定为违反，删掉滑块、固定中位数即可（一行改动）。

## 6 接口契约（E 消费端）

字段命名以 B 的 `assets_index.json` 为准（`plant_id` / `has_cutout` / `height_range_cm` / `dominant_hex` / `light_level` / `pet_safe`），不自造同义词。前端已就位、等后端填的四处：

1. `GET /api/plants` → 等价于 `assets_index.json` + `plants_master.csv` 的合并（前端现在自己合，接口到位后删掉合并逻辑）。
2. `POST /api/photo/check` → `{usable, ground_detected, issues[{code,level,msg}]}`，`code` 枚举 `TOO_DARK/TOO_BRIGHT/BLURRY/NO_GROUND/TOO_SMALL/BAD_ANGLE`。
3. `POST /api/compose` → 入参 `{session_id, anchor{ground[[x,y],[x,y]], px_per_m, ref}, plants[{plant_id,x,z,height_cm,asset}], options{color_match,shadow,out_long_edge}}`；出参 `{ok, image_url, elapsed_ms, warnings[]}`；错误码 `PHOTO_NOT_FOUND/ANCHOR_INVALID/ASSET_MISSING/TOO_MANY_PLANTS/COMPOSE_TIMEOUT`。
4. `POST /api/score` → 与 `/api/recommend` 的 `score` 字段**完全同构**（`aesthetic/adapt/final/dims{7维}`），另加 `suggestions[]` 与 `conflicts[]`；要求 P95 ≤ 300ms（前端 250ms 防抖）。

## 7 部署方案（华为云，课程第 5 条）

拓扑：`2C4G ECS（Ubuntu 22.04）→ nginx :80/:443 → gunicorn（3 workers × 2 threads，127.0.0.1:8000）→ Flask app`，静态资源与 `assets/` 由 nginx 直接出，不经过 Python（否则 12MB 素材会把 worker 占满）。

步骤（W4 周三门禁 G4 前必须全部跑通）：

1. 安全组开 80/443，22 只对自己的 IP；
2. `apt install python3-venv nginx`；仓库 clone 到 `/opt/verda`；
3. venv + `pip install -r scripts/requirements.txt`（D 维护）；
4. `/etc/systemd/system/verda.service`：`ExecStart=/opt/verda/.venv/bin/gunicorn -w 3 -k gthread --threads 2 -b 127.0.0.1:8000 app:app`；
5. nginx：`/` → gunicorn，`/assets/` `/data/` → 直接 root 到目录，开 `gzip` 与 `expires 7d`；
6. 冒烟：`curl -I` 三个路径（首页、素材、接口）＋ 一次上传合成全链路；
7. 手册落到 `docs/13_部署手册.md`，并让 **D 照着跑一遍**（分工表点名的单点风险：E 同时承担画布与部署）。

风险：Week 4 部署与答辩撞车 → 所以部署脚本与手册提前到 W3 写、W4 周一必须上云，G4 不过就用临时隧道演示 + 录屏兜底。
