# 7 质检 SOP：9 项自动 + 5 项目检

质检的目的不是「证明我做得好」，而是「让不合格的图在进库前就被拦住」。所以规则必须可判定：要么有阈值，要么有明确的目检问题清单，不能是「看着还行」。

## 7.1 自动检查（`qc.py`）

| # | 检查 | 阈值 | 判定 | 不通过怎么办 |
|---|---|---|---|---|
| 1 | alpha 通道存在 | RGBA | fail | 重跑去底 |
| 2 | 长边 | ≥1200px | fail | 换源图 |
| 3 | 主体占比 | 4%–85% | fail | 重新裁切或换源 |
| 4 | 边缘透明比例 | 不透明 ≤10% | fail | 修边或重跑 |
| 5 | 最大连通域 | ≥80% | warn | 目检是否多株/碎片 |
| 6 | 色温 | b* 中位数 ≤22 | warn | 校色后重存 |
| 7 | 命名规范 | `Pxx_front_源.png` | fail | 改名 |
| 8 | 来源 URL | 非空 | fail | 补授权 |
| 9 | 许可字段 | 非空 | fail | 补授权 |

第 5 项用 256px 缩略图算连通域，细叶植物（文竹、蕨类）容易掉到 0.8 以下。这不是误判，是提示「这片叶子可能断了」，需要人看一眼。第 6 项用 CIELAB 的 b* 判色温，比肉眼可靠：b* 偏正发黄，偏负发蓝，绝对值超过 22 基本能看出脏。

## 7.2 人工目检（5 项，约 30 秒一张）

- **正面平视**：叶面朝向镜头，不是从上方俯拍；俯拍图合成后一定「趴」在地上。
- **单株无遮挡**：画面里没有第二株、没有手、没有花盆挡住主茎。
- **叶色真实**：没有过饱和、没有滤镜偏色；与 `dominant_hex` 对得上。
- **阴影自然**：合成后接触阴影不超出叶冠投影范围，不出现「剪纸贴上去」的硬边。
- **无文字水印**：包括角落小字、账号名、平台 logo。

## 7.3 三态处置

| 判定 | 含义 | 处置 |
|---|---|---|
| pass | 全部达标 | 状态置 ready，可进合成与主视觉 |
| warn | 有非致命问题（色温/多株嫌疑） | 入库但 note 写明，不进答辩主视觉 |
| fail | 硬性不达标 | 状态 rejected，退回去底或换源，不入库 |

## 7.4 抽检比例

- **素材 100% 全检**：36 张，脚本跑一遍不到 1 分钟，没有理由抽检。
- **案例 10% + 每格至少 1 张**：120 张抽 12 张，且 30 个配额格每格至少看 1 张，防止某一格整体跑偏。
- **授权表 100% 反查**：`package.py` 逐文件比对授权行，缺行直接列出来。

## 7.5 输出长什么样

```text
待检素材 10，案例 0
  OK   A-P01 1600px a=31% b*=+3
  WARN A-P05 1600px a=18% b*=+4 疑似多株/碎片 最大连通域 76%
  FAIL A-P12 1600px a=44% b*=+2 边缘未去净 24%
结果：pass 8 / warn 1 / fail 1
有 fail 项：先修素材，不要入库。
```

`qc_report.csv` 与上表同源，字段为 item / type / plant_id / file / verdict / issues / long_edge / alpha_ratio / border_alpha / component / b_star，A 验收时直接看这张表。

## 7.6 返工优先级

返工按「影响合成效果」排序，不按发现顺序：

1. `component < 0.8`（细叶断裂）——合成后叶子缺一块，最扎眼；
2. `border_alpha > 0.15`（背景残留）——浅色墙面上会出现灰边；
3. 长边 <1200——放大糊，但只在导出大图时暴露；
4. 色温偏差——可以用 D 的色温匹配兜一部分，优先级最低。
